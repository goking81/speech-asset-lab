# F7-02｜Golden Set、Provider 兼容、发布与回滚

## 目标

为已启用的 AI 角色建立可重复的发布质量门禁、Provider/模型兼容记录，以及候选 Bundle 的批准、激活、撤回与审计闭环。新发布只影响新会话；历史会话继续使用其冻结 Bundle。

## 必做

1. 建立 Golden Set Runner，可按 AI 角色和冻结输入重复运行，并保存结构化结果、失败原因、运行环境与 Bundle 引用；
2. 建立角色级回归门禁，明确 R1—R7 各角色的可用性、结构校验和安全降级结果；不得将测试输出写入正式资产、回答、训练记录或用户掌握状态；
3. 建立 Provider/模型兼容矩阵，记录受支持组合、配置状态、测试时间、兼容结果和安全回退；密钥始终只保存在现有受保护配置边界内；
4. 实现 AI Release Bundle 的候选、批准、激活、撤回状态与审计记录。未经 Golden Set 通过和人工批准的候选不得激活；
5. 实现发布报告、回滚到已批准历史 Bundle，以及可验证的回滚演练；
6. 保证旧会话的 Bundle 冻结引用不可改写，新会话才可读取新的已激活 Bundle；
7. 增加迁移、Golden Set 可重复性、发布门禁、兼容回退、审计和回滚端到端测试，并更新 RESULT.md。

## 禁止

- 未通过 Golden Set 或未经人工批准就激活 Bundle；
- Provider 切换没有明确的回滚路径；
- 用真实用户回答、训练记录、正式资产或密钥作为 Golden Set 测试输出；
- 改写历史会话已冻结的 Bundle，或让发布自动覆盖任何用户内容；
- 引入账号系统、云端发布、支付、音频、实时语音或超出 MVP 的完整 Agent。

## 验收

- Golden Set 可在同一冻结输入上重复运行，并得到可审计的结构化结果；
- 角色级门禁和 Provider/模型兼容状态可查看，失败时维持既有安全降级；
- Bundle 的候选、批准、激活和撤回均有审计，未通过候选无法激活；
- 回滚可验证，历史会话仍读取原冻结 Bundle，正式资产、训练记录和用户回答不被改变。
