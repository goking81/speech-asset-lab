# F4-03｜R6 受支撑追问与失败直达重答

## 目标

在 P08 第一次回答后实现最多三轮、每轮只含一个问题的受支撑追问。每条追问必须能回溯到当前已冻结问题计划中的义务和支撑；R6 不可用、结果无效或用户选择结束时，必须保留已保存输入并进入空白的第二次回答。

## 必做

1. 为 P08 会话冻结可用 R6 Release Bundle；用户第一次回答或追问回答先持久化，再创建对应 R6 `AiTask`；
2. 实现 0—3 轮 `FollowUpItem`：每轮仅一题，保存 `issuedIndex`、问题文本、支撑证明、状态和结束原因；
3. 仅允许问题计划中已冻结的义务、个人资产节点、已确认事实或题面上下文成为追问支撑；AI 返回的支撑引用必须经本地验证；
4. 追问回答沿用 `trim(text).length > 0` 门禁，单字符和标点可以保存，且每轮与序号一一对应；
5. 处理无支撑、无进展、内容已完整、达到三轮上限、用户结束、Provider 未配置/超时/失败和结构无效：均要可解释，并安全进入第二次回答；
6. 更新 `/practice/[sessionId]`：展示当前单题追问、其支撑边界、输入/草稿恢复与“结束追问并开始第二次回答”操作；
7. 补充 R6 发布 Bundle、服务端/状态机/失败降级测试与端到端回归，并更新验收记录。

## 禁止

- 随机陌生追问、没有本地支撑证明的追问、一次展示多题或超过三轮；
- 因 AI 失败、无效结构或用户结束而删除第一次/追问回答，或阻塞进入第二次回答；
- 对追问回答设置词数、句数、字符数或“内容太短”提交门槛；
- 显示第一次回答的正式 R7 评价，或自动复制第一次回答到第二次；
- 改变来源资产、个人资产、问题计划、训练资格或正式状态。

## 验收

- 每条 READY 追问都有已验证的 `supportProofJson`，且其引用属于冻结问题计划；
- 追问回答先保存；同一幂等键不产生重复 Answer 或重复 FollowUpItem；
- 最多三轮；达到上限、内容完整、无进展或用户结束时均以可读原因进入第二次回答；
- Provider 未配置、超时、结构无效、无支撑或会话陈旧时不丢失输入，且可直接进入第二次回答；
- 第二次输入始终从空白草稿开始，刷新后可恢复当前追问草稿。
