# 生产版本控制

本项目采用“Git 提交 + 发布标签 + Cloudflare Worker 版本”三层回退方式。

## 发布规则

1. 每次准备发布前，先完成独立且可读的 Git 提交；不把无关改动混入发布提交。
2. 通过本地检查后，为该提交建立带说明的 Git 标签，格式为 `release-YYYY.MM.DD-主题.序号`。
3. 推送 `main` 与标签。Cloudflare 的 Git 构建以 `main` 的确切提交为输入；构建成功后，把 Worker 版本 ID、正式 URL 与验证结果记录到发布记录中。
4. 生产数据库、密钥、来源资料和本地数据库永不进入 Git 提交或标签。

## 回退规则

- **仅回退线上运行版本**：在 Cloudflare Workers 的版本页面选择上一个已验证版本回滚。这不改写 Git 历史。
- **需要让代码也回到旧版本**：以目标发布标签创建 `git revert` 提交并推送 `main`；不要使用 `reset --hard` 或强制推送改写公共历史。
- **紧急情况**：先用 Cloudflare 回滚恢复访问，再创建可审计的 Git 回退提交并补齐发布记录。
