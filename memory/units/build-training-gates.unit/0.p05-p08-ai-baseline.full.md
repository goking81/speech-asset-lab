# Iteration 03｜训练门禁与 AI 基线（完整）

## 已确认决策

1. 门禁从纯函数导出，客户端测试页和服务端服务复用，不把产品规则散落在按钮事件中。
2. P05 第 2—4 步只保存用户口头自报；没有任何音频、录音、转写或发音判断实现。
3. P08 的服务端先完成 Answer 持久化，再在同一事务创建 R7A AiTask。有效输入不按词数、句数、字符数或关键词阻断。
4. 训练会话必须仍是当前业务版本、未失效且绑定 ACTIVE Release Bundle；发布包被会话冻结。
5. Mock AI 的正常结果是待用户确认的草稿；不足文本进入 `NEEDS_REVIEW` 且保留 Answer；Provider 未配置、超时或失败进入 `FAILED_RETRYABLE`；过期任务进入 `SUPERSEDED`。

## 主要实现

- `AnswerSubmissionService` 使用 SHA-256 标准化 fingerprint、数据库 transaction 和 unique/upsert 提供幂等。
- `AiTaskOrchestrator` 对 AiTaskAttempt 记录 Provider/状态，不具备发布或覆盖用户内容的能力。
- `ReleaseBundleRegistry` 只暴露 active 的不可变定义。
- `/practice/gates` 是无副作用的验证页面；通过真实浏览器、Playwright 及 Vitest 验收。

## 后续约束

- 后续接入 HTTP/API/队列/Provider 时，不得改变“先保存、后 AI、AI 草稿、用户确认”的顺序。
- 后续正式页面应调用现有服务和门禁，而非复制判断条件；必须继续支持单字符和标点提交。
- Iteration 03 仍等待审核，不得自动进入 Iteration 04 或 F1。
