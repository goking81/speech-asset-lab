# Prompt 与 AI Coach 规则｜开发封版摘要

版本：0.3  
更新日期：2026-07-23

## 1. 角色链路

- R1：候选语流资产提取；
- R2：来源资产编辑、规范学习版和 changeSet；
- R3：个人资产生成；
- R4/R4A：受支撑问题、义务和回答骨架；
- R5：今日计划编排；
- R6：0—3 轮受支撑追问；
- R7A：资产调用识别；
- R7B：六维评价；
- R7C：两次回答解释。

同一训练会话冻结 AiReleaseBundle，中途不得混用 Prompt、Schema 或策略版本。

## 2. 本地规则优先

AI 不负责：阶段判断、资产资格、拼贴解锁、任务优先级、提示升级、正式状态更新、总分计算和发布。

## 3. 输入保存顺序

所有用户编辑、第一次回答、追问回答和第二次回答必须先保存，再创建 AI Task。输入指纹变化后旧结果标记 SUPERSEDED，不得覆盖当前状态。

## 4. P05 影响

P05 第 2—4 步没有音频输入，因此不触发任何语音 AI 角色。仅保存用户自报尝试。第 5 步的文字回答可进入锚点问题评价；Prompt 上下文不得声称观察到口头过程。

任何 Prompt 中涉及“流利度”的描述必须限定为**提交文字的思想连续性**，不得扩展为真实口语流利度。

## 5. P08 非空输入规则

AI 输入前置校验只检查：

- 会话/版本有效；
- 回答经 trim 后非空；
- Answer 已持久化；
- Release Bundle 可用。

禁止在调用前使用词数、句数或关键词命中作为阻断。R7A/R7B 可在调用后返回不足状态：

- `INSUFFICIENT_TEXT`；
- `INVALID_CONTEXT`；
- `UNAVAILABLE`；
- `NEEDS_REVIEW`。

这些状态不得回写为 0 分或无调用。

## 6. R6 追问

- 0—3 轮；
- 每次只问一个最高价值缺口；
- 问题必须有 approved asset、确认个人事实或题面上下文的支撑证明；
- 无支撑、重复无进展、用户结束、内容已完整或达到上限时结束；
- R6 失败不得用随机问题兜底，允许直接进入第二次回答。

## 7. R7 评价

1. R7A 先识别资产调用和节点证据；
2. R7B 六维中“资产调用”锁定为 R7A 本地正式结果；
3. 模型不计算总分；本地按 25/20/15/15/15/10 加权；
4. R7C 只解释本地冻结的比较事实；
5. 提示和追问不进入六维原始评分，只作为支持条件；
6. R7B 失败不得伪造分数；R7C 失败使用本地模板。

## 8. P05 逻辑节点展示数据

R1/R2/R3 输出仍需提供节点 ID、NodeType、节点文本或稳定文本范围。模型不得输出 UI 颜色。前端根据 NodeType 映射颜色。

## 9. Provider 失败降级

- R1—R3：保留来源、编辑和草稿，允许重试或人工继续；
- R4：无支撑不得随机生成问题；
- R5：使用本地默认计划；
- R6：直接进入第二次回答；
- R7A/R7B：显示部分结果或不可评价，不伪造；
- R7C：展示本地比较事实和模板。
